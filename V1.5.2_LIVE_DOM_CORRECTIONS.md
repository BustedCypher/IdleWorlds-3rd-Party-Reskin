# v1.5.2 — Live DOM Corrections

This build corrects two issues exposed by live IdleWorlds screenshots after the v1.5.1 HUD/Skills refinement.

## Player name visibility

The HUD classifier was correctly identifying the player-name wrapper, but IdleWorlds can apply its dark text colour to a nested descendant. Because that child owns its own colour, styling only the wrapper did not reliably override it.

v1.5.2 now marks both the detected player-name shell and the actual detected text node. The shared HUD CSS forces readable foreground colour, text fill, opacity, and removes native text/background effects through the nested name subtree. No username is hard-coded.

The identity roles are also cleared and recalculated on each reconciliation so stale role assignments cannot survive a React header update.

## Skill XP readout boxes

The live skill DOM nests the `LV xx - xx.x% • x TO GO` text inside multiple same-text wrappers. The visible border/background can exist on an intermediate wrapper. v1.5.1 only neutralised the outermost shell, which left the intermediate metric-card styling visible.

v1.5.2 walks the full same-text wrapper chain and neutralises every layer: background, border, radius, shadow, padding, margin, width/min-width and height/min-height. All marked layers also inherit the compact XP typography.

## Skill layout consistency

The three-zone skill layout previously required exactly three direct React children. Some skill panels include extra decorative/absolutely-positioned children, so the strict child-count gate caused the layout to apply inconsistently.

v1.5.2 accepts the three-zone layout whenever the identity, content and command branches are distinct and any extra direct children are non-flow decoration (hidden, absolute/fixed, or effectively zero-size). Any additional visible functional branch still disables the rigid layout as a safety fallback.

## Safety

- No React gameplay nodes are reparented.
- The central DOMWatcher remains the only MutationObserver.
- Unknown visible skill branches still fall back to the native layout.
- Existing v1.4.x/v1.5.x data-service and renderer regression tests remain in place.
