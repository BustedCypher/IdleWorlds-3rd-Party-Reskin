# IdleWorlds Fantasy Skin v1.5.0 — Shared RPG UI Foundation

This release builds on the v1.4.1 lifecycle fixes and v1.4.2 visual-correctness pass. It deliberately focuses on the global HUD/navigation and skill-panel system before applying the same primitives to Inventory, Market, Housing Bank, Salvage, Quests, World Bosses and Leaderboards.

## Shared UI foundation

- Added `UIFoundation.js`, which classifies existing React-owned DOM nodes with semantic `data-iw-ui` roles instead of rebuilding them.
- Added `ui-system.css`, defining shared frame, HUD, navigation, control, search and spacing primitives.
- No new MutationObserver was added; all reclassification is triggered by the existing central DOMWatcher.
- Major section frames are classified only from explicit headings and substantial containers, avoiding the old broad `[class*=panel]` / `[class*=card]` strategy.

## Global HUD and navigation

- Player HUD receives a forged-iron/brass frame and restrained identity accent.
- Stat/buff readouts are flattened from large rounded dashboard pills into compact HUD metrics.
- Main `Game / Market / Leaderboards / Village / Dungeon` navigation becomes a connected metal tab rail.
- Active tab state is inferred from semantic classes/ARIA first, route state second, and original warm background only on first classification.
- Search controls use recessed trough styling.

## Skills

- Skill panels now receive semantic role markers for identity, action title, action button, navigation controls, XP readout, XP gain, requirements, rewards, ingredients and progress bars.
- When the live React DOM exposes exactly three distinct direct zones, the panel opts into a strict `identity | content | commands` grid. Unknown DOM shapes remain on the native layout and receive role styling only.
- Skill action buttons use fixed heights/widths; navigation arrows use fixed square controls.
- Progress bars use a thin forged rail rather than a rounded modern web progress bar.
- Item references remain inline and readable rather than becoming button-like boxes.
- Added current skill recognition for Jewelcrafting (`Prospect`), Spellcrafting (`Enchant`) and Tailoring (`Tailor`/`Sew`). Prospect is no longer incorrectly treated as Mining.
- Existing Crafting/Fishing recognition remains as a compatibility fallback.

## Stability constraints retained

- React keeps ownership of gameplay DOM and event handlers.
- No skill panel reparenting.
- Exactly one runtime MutationObserver.
- Inventory renderer remains isolated from Market/Bank/Salvage.
- Runtime atlas revision remains immutable.
- Production bundle has no inline source map.

## Automated checks

`npm test` verifies data-service resilience, lifecycle invariants, semantic UI foundation registration, single-observer architecture, current skill detection, safe skill role layout, immutable atlas URLs and production bundle constraints.
