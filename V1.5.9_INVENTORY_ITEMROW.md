# IdleWorlds Fantasy Skin v1.5.9 — Inventory ItemRow Foundation

This pass starts from the stable v1.5.8 baseline and is intentionally scoped to Inventory presentation plus the existing delegated tooltip trigger API. HUD, Skills and the strict tooltip ownership lifecycle are otherwise unchanged.

## Goals

- Establish Inventory as the reference reusable RPG ItemRow.
- Keep every real IdleWorlds action button as the original React-owned DOM node.
- Use a consistent icon / identity / quantity / action geometry.
- Restore dynamic owned-item information that earlier compact rows hid.
- Avoid rebuilding Market, Housing Bank or Salvage as Inventory.

## Item information ownership

Stable data comes from ItemDatabase:

- item identity
- tier / slot
- base stats
- sockets and static bonuses

Dynamic owned-item state is extracted from the native Inventory row before display-only branches are suppressed:

- loadout membership
- socketed gem / affix lines
- repeated socket effects (compressed as ×N)
- requirements
- upgradability state
- other compact `Label: +N` dynamic effects

This is deliberately conservative: native action controls are never recreated.

## Action rail

Real controls are classified semantically as:

- Equipped / Unequip
- Equip
- Set bonus
- secondary action (List / Use / Sell where applicable)
- icon action (Lock / Unlock)

The skin gives these roles deterministic widths and shared forged-metal styling while preserving the game's event wiring.

## Tooltip integration

Both the rendered item name and the item icon can open the same delegated tooltip. Icons use `data-iw-tooltip-trigger="1"` so they do not inherit the inline text-reference CSS used by `.iw-item-ref`.

The v1.5.8 hover-ownership rule is unchanged: desktop tooltips disappear immediately when the pointer owns neither the originating trigger nor the tooltip card.

## Inventory chrome

Only a positively identified Inventory root receives the compact Inventory-specific title, filter, pagination and icon-control roles. These rules are scoped and do not affect Market, Bank, Salvage or generic buttons.

## Responsive behavior

- Desktop keeps dynamic details visible and actions aligned on the right.
- Medium widths reduce icon/stat density.
- Narrow layouts collapse secondary detail lines while preserving identity, quantity and primary actions.

## Verification

Automated checks cover:

- existing data-service resilience tests
- pure InventoryModel parsing for complex/socketed/loadout/requirement/plain-stack examples
- one-MutationObserver invariant
- inventory-context gating
- React action preservation
- icon tooltip opt-in
- source syntax and production bundle invariants
