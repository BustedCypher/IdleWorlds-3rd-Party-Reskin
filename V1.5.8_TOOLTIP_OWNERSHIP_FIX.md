# IdleWorlds Fantasy Skin v1.5.8 — Strict Tooltip Hover Ownership

This pass is intentionally isolated to the tooltip lifecycle. It preserves the v1.5.7 live-DOM/UI baseline.

## Root cause found

`TooltipEngine.position()` wrote `opacity: 1` as an inline style while measuring/positioning the card. `hide()` only removed the `.is-open` class. Because inline opacity wins over stylesheet opacity, the card could remain visibly rendered after its trigger was no longer hovered. The old 180 ms hide grace could further make stale cards appear to linger.

## Desktop behavior

- Tooltip opens after the existing 120 ms hover-intent delay.
- Tooltip closes immediately when the pointer is no longer over either:
  1. the item reference that opened it, or
  2. the tooltip itself.
- No hide grace timer remains.
- Trigger and tooltip are positioned with a 0 px gap so the pointer can move directly onto the interactive tooltip without crossing dead space.
- Moving directly from trigger to tooltip, or tooltip back to trigger, keeps it open.
- Moving to another item closes the old tooltip immediately before the new hover delay begins.
- A document-level mousemove ownership check catches missed leave events and React node replacement.
- DOM flushes, scrolling, resizing and data refreshes cannot resurrect/orphan a tooltip when the pointer no longer owns it.
- Hiding uses `display:none` in addition to removing `.is-open`, so CSS/inline opacity cannot leave a visible ghost.
- Tooltip opacity transitions are disabled; close is immediate.

## Touch behavior

Touch/coarse-pointer devices retain tap-to-toggle behavior because there is no hover state to own the tooltip.

No additional MutationObserver is introduced and no gameplay renderer/UI layout code is changed.
